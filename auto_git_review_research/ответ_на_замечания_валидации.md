## Замечание 5. Отсутствуют trace-логи (промпты, ответы, latency, токены, end-to-end)

**Приоритет:** Высокий.

**Статус:** исправлено.

**Что сделано:**

- `llm.py` — `chat()` теперь возвращает словарь `{content, reasoning, usage,
  latency_ms}`; логирует промпт и ответ на уровне DEBUG, а на уровне INFO —
  строку `LLM ответ: latency=…ms, tokens=…` с разобранным `usage` (prompt /
  completion / total);
- `review.py` — замер end-to-end латентности на каждый PR (`latency_ms`) и
  накопление токенов (`tokens`) по всем вызовам LLM в рамках PR; результат
  каждого PR несёт `pr_id`, `verdict`, `latency_ms`, `tokens`;
- `monitoring.py` — `emit_summary()` логирует итоговую сводку прогона одной
  структурированной JSON-строкой `REVIEW_RUN_METRICS {…}` (итог по вердиктам,
  суммарная латентность, суммарные токены, оценка стоимости).

## Замечание 7. Качество модели не проверено

**Приоритет:** Высокий.

**Статус:** в работе (прогон в корпоративном контуре).

**Что сделано:** заложен механизм прогона eval — `eval.py` реализует
`evaluate(reviewer, dataset)`, где `reviewer` — подключаемый callable, возвращающий
вердикт модели по кейсу; рассчитываются accuracy, Precision / Recall / F1 по
каждому классу (`approve` / `request_changes` / `comment`) и confusion matrix,
формируется markdown-отчёт (`write_report`). Метрики привязаны к целевым значениям
из `README.md` (accuracy ≥ 80%, Precision / Recall ≥ 0.7).

Живой прогон с моделью и датасетом требует доступа к ALM/LLM в корпоративном
контуре — выполняется после наполнения golden set (замечание 6).

## Замечание 8. Отсутствует мониторинг качества / latency / cost

**Приоритет:** Высокий.

**Статус:** исправлено (инфраструктура) / в работе (пороги и алерты).

**Что сделано:** `monitoring.py` — `summarize()` агрегирует результаты PR в
сводные метрики (количество PR, распределение по вердиктам, суммарная латентность,
суммарные токены, оценка стоимости `COST_PER_1K_TOKENS`); `emit_summary()` пишет
сводку одной JSON-строкой `REVIEW_RUN_METRICS {…}`, пригодной для разбора
ELK / Prometheus-экспортером. Вызов `emit_summary` встроен в конец
`review.run_review()`.

Настройка порогов и алертов по этим метрикам — на стороне эксплуатации в
корпоративном контуре (требуется реальный прогон для калибровки порогов).
